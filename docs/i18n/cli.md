# @rivinia/i18n — the CLI: language module and typed keys

Back to [the README](../../projects/i18n/README.md) ·
[translating text](translating.md) · [the API](api.md)

Two commands ship with the package: `ng add @rivinia/i18n` (a schematic) and the
`rivinia-i18n-keys` binary (three modes — `init`, key generation, `--parity`).

## `ng add`

```bash
ng add @rivinia/i18n
```

It asks for the language ids (comma-separated; the first is the default) and
whether to detect the browser language — both are also options (`languages`,
`detectBrowser`, plus `project` for a multi-app workspace), so CI can pass them
on the command line instead of answering questions. It only inserts an import and
a `provideRiviniaI18n({…})` call, is idempotent, and skips with a warning — never
an error — when it does not recognize the workspace.
`@angular-devkit/schematics` is an **optional peer** declared for exactly this
command; an app that never runs `ng add` does not install it.

## Generating the language module

Writing the language list by hand is the one boilerplate this package still
asked for. `init` collects it once and writes the module plus one empty
dictionary per language:

```bash
npx rivinia-i18n-keys init
# [rivinia/i18n] Language id (ar, en, ar-EG …): ar
#   Native name [العربية]:
#   Direction (ltr/rtl) [rtl]:
#   Another language? (Y/n): y
# [rivinia/i18n] Language id (ar, en, ar-EG …): en
#   Native name [English]:
#   Direction (ltr/rtl) [ltr]:
#   Another language? (y/N): n
# [rivinia/i18n] Default language — (1) ar  (2) en [1]:
```

That writes `src/app/i18n/languages.ts`:

```ts
// Generated by `npx rivinia-i18n-keys init`. Re-run the command to regenerate.
import { defineRiviniaI18n } from '@rivinia/i18n';

export const i18n = defineRiviniaI18n({
  defaultLanguage: 'ar',
  languages: [
    { id: 'ar', nativeName: 'العربية', dir: 'rtl' },
    { id: 'en', nativeName: 'English', dir: 'ltr' },
  ],
});

/** The typed language manager — call inside an injection context. */
export const injectI18n = i18n.inject;
```

and `public/i18n/ar.json` / `public/i18n/en.json` (each `{}`; an existing
dictionary is kept untouched). The module keeps the `'ar' | 'en'` union, so the
components stay short:

```ts
// src/app/app.config.ts
import type { ApplicationConfig } from '@angular/core';
import { i18n } from './i18n/languages';

export const appConfig: ApplicationConfig = {
  providers: [i18n.provide()],
};
```

```ts
// any component — field initializer or constructor body
import { injectI18n } from './i18n/languages';

private readonly i18n = injectI18n();
```

`i18n.config` is the same object, so `i18n.config.languages` stays `'ar' | 'en'`
wherever it is imported.

`dir` is explicit rather than derived at runtime, so an Urdu or Hebrew dictionary
cannot silently render left-to-right. Ids, directions and duplicates are
validated before anything is written.

| Flag          | Effect                                                                       |
| ------------- | ---------------------------------------------------------------------------- |
| `--languages` | `id[:nativeName[:dir]]` pairs, comma-separated — skips the questions for CI. |
| `--default`   | Default language id; the first one listed when omitted.                      |
| `--out`       | Module path, default `src/app/i18n/languages.ts`.                            |
| `--dir`       | Dictionary folder, default `public/i18n`.                                    |
| `--dry-run`   | Print the files without writing them.                                        |
| `--force`     | Replace `<out>` even when it was not written by this command.                |

Without that flag a `languages.ts` carrying no generated-file banner is left
alone and the command exits 1 with a message, so a hand-written module is never
clobbered by a re-run.

## Typed keys

Every key is a plain `string` until you generate the declaration. The registry
(`RegisteredI18nKey`, `RiviniaI18nKeyRegistry`) is empty by default, so nothing
breaks in an app that never runs the command. Generate it from a dictionary and a
typo becomes a compile error:

```bash
npx rivinia-i18n-keys
# → src/i18n-keys.d.ts
npx rivinia-i18n-keys --source public/i18n/en.json --out src/i18n-keys.d.ts
npx rivinia-i18n-keys --check   # exit 1 when the file is stale (CI)
npx rivinia-i18n-keys --parity --dir public/i18n --base en
```

Bare, the command uses the conventional layout: source `public/i18n/en.json`,
output `src/i18n-keys.d.ts`, parity directory `public/i18n`, parity base `en`.

```ts
// src/i18n-keys.d.ts — generated, do not edit
import '@rivinia/i18n';

declare module '@rivinia/i18n' {
  interface RiviniaI18nKeyRegistry {
    readonly keys: 'app.title' | 'app.save' | 'booking.seats';
  }
}
```

With that file in the program:

```ts
i18n.translate('app.title'); // ok
i18n.t('app.titel'); // TS error: not assignable to 'app.title' | …
i18n.translate(`status.${code}` as RegisteredI18nKey); // dynamic key, explicit
```

The CLI flattens nested objects to dot paths, keeps literal dotted keys as-is,
keeps string leaves only, warns about non-string leaves and key collisions (the
flat key wins), sorts keys for stable diffs, and escapes quotes. It has no
dependencies and ships with the package (`rivinia-i18n-keys`).

`--check` regenerates into memory and exits 1 when the file on disk differs — the
form CI runs when the dictionaries change but the declaration does not.

`--parity` compares every `<language>.json` in `--dir` against `--base` and
reports, sorted: keys missing from a language, keys extra to it, and ICU
placeholders used by the base string but absent from the translation.
Placeholders inside plural/select branches are compared too; branch text itself is
never read as a parameter. Any mismatch exits 1, so CI fails on the common "added
to `en.json`, forgot `ar.json`" bug.
