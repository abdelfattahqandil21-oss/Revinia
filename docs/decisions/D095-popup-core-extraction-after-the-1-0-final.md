- Context: `select-popup.ts` and `menu-panel.ts` duplicate popup positioning and dismissal logic. D86 correctly deferred the extraction before 1.0 and required a shared conformance suite so one host could not drift from the other. The owner task now explicitly approves extraction groundwork for the post-1.0 line.
- Decision: prepare `@rivinia/popup` as a headless package for the generic, behavior-equivalent popup logic. Keep the conformance suite and its mutation checks as the behavioral contract before and after each move. This branch is local groundwork only; it does not change existing public APIs, versions, release-group membership, registry state, or the 1.0 release.
- D86 remains authoritative for the conformance requirements and the observed behaviors. This decision supersedes only its timing restriction (“no dedupe before 1.0”), not its test coverage, resize policy, or evidence.

- Select and Menu consume `@rivinia/popup` as a regular dependency, not a peer, so each consumer installation receives the core. The core's only peer is `@angular/core`; its package is headless, has `sideEffects: false`, and exposes one entry point unless a demonstrated need justifies another.
